把一章地理课本，做成一个能自己算数的网站

这是我在高中阶段给自己搭的一门课。AmaAstro 是署名。 起因很简单：我能判断性质——夏至昼长夜短、直射点在北半球——但给不出一个具体的数。 没学过球面几何，于是每到要算的时候只能背结论。这门课就是冲这个缺口去的。

这是什么

一门高中地理「地球运动」的完整课。教材基准是人教版选择性必修一第一章， 范围与深度对着教育部《普通高中地理课程标准》定——选择性必修 1 的内容要求 1.1， 以及学业质量水平 3-2 / 4-2。

主线不是"背结论"，而是一条能自己走通的因果链：

黄赤交角 → 地轴与阳光的夹角 → 太阳直射点往返 → 正午太阳高度与昼夜长短 → 四季与极昼极夜

每个节点都是一课，含讲解、自己产的配图、练习题（选择题点选即时判分，开放题附参考答案与判分要点）。

我给自己定的两条硬规矩

一、数据必须来自权威来源，并且逐条对过

课里出现的每一个官方数字，都来自可追溯的来源并对过表：

  • 教材范围：人教版选择性必修一第一章的官方目录记录
  • 深浅标准：教育部《普通高中地理课程标准（2017 年版 2020 年修订）》
  • 太阳位置数据：香港天文台的年历与二十四节气表——它给出每个中气的 太阳直射点纬度圈、上中天时间与仰角、日出日落方位角

举个具体的对表：用 正午太阳高度 = 90° − |纬度 − 直射点纬度| 复算香港十二个中气，全部落在天文台公布整数值的 1° 以内。

二、图上的每个角度都要能算出来，不能"看着差不多"

配图全部是自己算坐标、写 SVG 画的。这条规矩是被自己坑出来的—— 有一版图把「地轴与铅垂线成 23.5°」量在了错误的一侧，实际画成 66.5°， 而"晨昏圈垂直于阳光"这个关系就跟着不成立了。 后来写了个量角脚本，一测就露：夹角 67.86°，而它必须正好是 90°。

现在每张涉及角度的图都要过一遍脚本核算：晨昏圈与阳光的夹角、弧线两端到顶点的半径、 节气点是否落在曲线上、文字框有没有互相压住。图上每个数字都来自这些核算，不是目测。

过程中的两个工程问题

课程本身是"内容"，但要做成能用的东西，绕不开两个工程问题。这两块是我觉得最值得说的部分。

把一课打包成一个 HTML 文件

课件页面本身引用了九个文件（样式、主题、公式排版、题目交互）， 外加 KaTeX 的二十个字体文件。单独把一个 .html 发出去，对方打开只会看到 没有样式、公式不显示、题目点不动的纯文本。

所以我写了个打包器：把样式与脚本内联进页面、把字体转成 data URI 内嵌， 最后出来一个 约 780 KB 的独立文件——发给任何人，双击就能学。

过程中踩到三个坑，都是量出来才发现的：

  • 带 src 的 <script> 标签没摘干净——浏览器会去请求一个 不存在的相对路径，还会让脚本执行两次
  • 字体的 MIME 类型被写成 application/octet-stream—— 浏览器对字体有类型白名单，会被拒绝加载，公式里的根号与积分号就会掉成默认字体
  • 写了个校验脚本，它连续三次把「注释里的说明文字」当成「没打干净的引用」报警—— 工具报的"问题"本身也是证据，得先验证它是不是真问题

做一个离线的安卓版

静态网页要在手机上用，最麻烦的是"本地文件打不开"。 为了把课程装进一个离线 App，试了五条路，每条失败的方式都不一样：

  1. file:///android_asset/ 直接读 → ERR_FILE_NOT_FOUND （Android 10 起收紧了 file:// 的读取）
  2. 假域名 + 拦截请求 → ERR_HTTP_RESPONSE_CODE_FAILURE（返回的响应被判为失败）
  3. App 内部起一个真的 HTTP 服务器 → 白屏；加了屏上诊断后发现「请求 0」， WebView 根本没连上它
  4. 把 APK 里的 HTML 读出来直接注入 → FileNotFoundException， 而那个文件明明在包里（"文件在包里却读不到"）
  5. 把课程内容在编译期变成代码里的字符串常量 → 成了

最后这条路绕开了所有外部依赖：运行时内容已经在内存里， 没有文件、没有 URL、没有端口。代价是包变大，换来的是"装上就能用"。

同一条路上还修掉两个安卓工具链的坑：资源打包器对某个目录结构静默失效（退出码 0 但产物是空的）， 以及 build-tools 34 自带的 d8 在 JDK 21 下会抛空指针——换成 build-tools 35 才通。

我是怎么做这些内容的

课的内容、配图与题目，是在一个 AI 学习助手的配合下产出的，按角色分工： 有人负责讲、有人负责出题与判分、有人负责查资料。我做的事是另外三件：

  • 定范围与验收：哪些内容进、哪些不进（明确不学大气运动、水循环）， 以及"什么算做完了"
  • 验算与对表：官方数据逐条核对，图上角度逐个量—— 上面那条 67.86° 的错误就是这么抓出来的
  • 判断与纠偏：模型给的东西不一定对。有一处极昼边界的数字算错了 （写成 69°48′，正解是 69°42′），是我复核时发现并改掉的

所以这份作品里有它该有的东西：一个真实的目标、可追溯的数据、 自己写脚本验证过的图，以及一段试错记录。工具是新的，验收是我做的。
